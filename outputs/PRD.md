# LifeFlow 产品需求

版本 0.2｜2026-11-06｜当前交付 0.1，待用户审核。

## 已确认方向

产品为带 AI 功能的私人生活助理 App，不设计自主 Agent／开放工具执行循环。大学生及年轻用户是目标用户，首版以时间管理为核心，暂不做复杂任务；饮食与视觉后置。主要 iPhone 验收，尽早验证 Capacitor。

React + TypeScript + Vite、Tailwind CSS、Node.js + Express、SQLite；后续文本 AI 使用 DeepSeek，密钥仅服务端。初期在 Windows／Mac 运行后端，未来部署自购云服务器，最终为 App Store 正式软件。

用户已授权初始化代码及两个公开 lifeflow 仓库：GitHub／Gitee，未授权部署。约 20 天、每天约 2 小时为暂定排期，不保证涵盖云端与上架。此前需求草稿留于 history/，不作为现行验收承诺。

## 使用流程

选择日期 → 在当天列中查看色块 → 点击色块查看／编辑 → 后端检查冲突与版本 → 保存成功后重新读取。新增默认选中日期；删除在编辑窗口中明确确认。任务是要做的工作，日程是时间占用，后续关联时不把安排当完成。

未来 AI：理解自然语言 → 读取必要的本人数据 → 输出建议／草稿 → 用户审阅 → 同一后端业务接口校验保存；模型不直接访问数据库，不后台自动改安排。当前 AI 状态页明确未接入。

## 业务边界

标题去空格后 1—120 字符，结束严格晚于开始；当前单项不超过 31 天，查询不超过 62 天。API 接收带偏移时间并保存 UTC，界面按设备时区显示，独立用户时区设置尚未实现。

半开时间区间允许相邻时段，重叠阻止保存，更新排除自身，跨午夜出现在涉及日期。事务内检查与写入；旧版本编辑／删除拒绝，当前新增没有自动网络重试或完整幂等账本。

所有者由服务端本地身份确定，前端不能指定。保留 ownerId、稳定 ID、更新时间和 version，为云端迁移准备；不是已经完成多用户隔离。

断连或保存失败不能显示成功；页面不预置模拟日程，不模拟 AI。照片将区分识别、份量估计与营养计算，确认后保存，不承诺精确测量或提供医疗诊断。

## 云端与原生预留

服务地址配置化，接口和持久化代码分开。本地身份未来认领到云账号；一次导入迁移不等于双向同步。云版需真实认证、隔离、限流、隐私同意、备份恢复和监控，再决定是否换数据库，不擅自更换 SQLite。

正式用户不应依赖个人电脑后端或开发 CA。首发地区、离线编辑、登录方式、收费、正式 Bundle ID 与许可证后续决定。原生凭据将使用平台安全存储，不把当前会话令牌当正式登录。
